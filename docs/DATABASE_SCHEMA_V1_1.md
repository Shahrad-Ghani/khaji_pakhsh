# Khaji Pakhsh — Modular Drizzle Schema

This package reorganizes the existing PostgreSQL V1.1 schema into domain-focused
Drizzle modules. It is a TypeScript code-organization refactor; it is **not** a
database migration and does not modify the physical PostgreSQL database.

## Included structure

```text
src/
└── db/
    ├── relations.ts
    └── schema/
        ├── admin.ts
        ├── media.ts
        ├── content.ts
        ├── catalog.ts
        ├── cms.ts
        ├── pricing.ts
        ├── seo.ts
        ├── settings.ts
        └── index.ts
```

## Table distribution

- `admin.ts`: admin users, roles, permissions, audit logs, and join tables
- `media.ts`: media assets
- `content.ts`: shared content and SEO identity records
- `catalog.ts`: products, brands, categories, attributes, and catalog join tables
- `cms.ts`: pages, revisions, navigation menus, and navigation items
- `pricing.ts`: current prices, price history, imports, price lists, and publications
- `seo.ts`: redirects
- `settings.ts`: site settings

## Corrections applied during the refactor

1. Five malformed Drizzle defaults were corrected to `.default("")`, matching
   the V1.1 SQL definitions.
2. Explicit `.op(...)` annotations generated by introspection were removed.
   The V1.1 SQL defines ordinary B-tree indexes without custom operator classes,
   so PostgreSQL should infer the correct default operator class from each column.
   Index columns, ordering, null ordering, and partial predicates are retained.
3. Content-item relations now reflect the composite `(content_item_id, content_type)`
   foreign keys and one-to-one cardinality. Join fields are declared on the FK-owning
   side; inverse `one()` relations are inferred by Drizzle.
4. Product-to-current-price is modeled as one-to-one.
5. Navigation parent/child relations use the correct composite mapping:
   `(menu_id, parent_item_id) -> (menu_id, id)`.
   The referenced unique constraint is `UNIQUE (menu_id, id)`. The Drizzle
   foreign-key declaration and relational mapping must preserve this exact column
   order.

## Pending database alignment

The Drizzle declaration for the SEO self-redirect check is being changed to a
case-insensitive comparison:

`lower(source_path) <> lower(target_path)`.

This is a schema-code change only until a corresponding new SQL migration is
created and successfully applied. The existing V1.1 migration files must remain
unchanged. Do not consider the Drizzle schema and physical PostgreSQL constraint
fully synchronized until that migration has been applied and verified.

## Integration notes

- Copy/merge the `src/db/` directory into the project root.
- Configure Drizzle Kit to read tables from `./src/db/schema/index.ts`.
- Keep the existing database connection/client configuration separate; this
  package intentionally does not replace `client.ts`, `.env`, or
  `drizzle.config.ts`.
- Do not execute the introspection SQL as a migration. Keep the original V1.1
  SQL and migration history as the source of truth.
- Do not run `drizzle-kit push` or apply a new migration as part of this
  refactor. First run TypeScript checks and compare the generated schema diff.
